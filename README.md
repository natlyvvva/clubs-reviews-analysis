# Анализ отзывов о ночных клубах Москвы

**Статус:** в процессе

## Задача
Рейтинг на картах — главный публичный сигнал для новых гостей и прокси их удовлетворённости. Цель проекта — понять, **какие проблемы сильнее всего снижают оценку заведения** и куда клубам направлять ресурсы в первую очередь.

**Гипотеза:** темы жалоб различаются по связи с рейтингом: одни упоминаются часто, но на оценку влияют слабо, другие встречаются реже, но сопровождаются заметно более низкими оценками.

## Данные
- 1 600 последних отзывов о 25 клубах Москвы из Google Maps (выгрузка через SerpApi, `src/club_reviews_api.py`); после очистки — 1 149 отзывов о 24 клубах с 2022 года, из них 834 с текстом
- Список заведений — `data/clubs.txt`
- Эталонная ручная разметка — 149 отзывов (`data/benchmark1.xlsx`)

## Что сделано
1. **Очистка и EDA:** покрытие выборки по клубам, отсечка отзывов до 2022 года, проверка статуса заведений (4 закрытых клуба выявлены по «молчанию» в данных и упоминаниям в тексте), доли негатива с доверительными интервалами Уилсона, проверка смещения выборки относительно официального рейтинга.
2. **LLM-классификация жалоб:** multi-label разметка отзывов по 10 темам (вход и фейсконтроль, персонал, цены, помещение и др.) с помощью Gemini 2.5 Flash, `temperature = 0`, промпт — `src/prompt.txt`.
3. **Валидация на ручной разметке:** Micro F1 = 0,79, Macro F1 = 0,75; для главной темы (вход и фейсконтроль) F1 = 0,90.
4. **Приоритизация проблем:** матрица «частота × индекс тяжести» (`5 − средняя оценка`), сравнение профиля жалоб между клубами.
5. **Проверка гипотезы регрессией:** OLS оценки отзыва на индикаторы всех тем одновременно (n = 834, R² = 0,61). Это разделяет вклад тем, которые часто встречаются в одном отзыве: 163 из 342 отзывов с жалобами содержат две и более категории.

## Ключевые результаты
- Жалобы есть в **41%** из 834 текстовых отзывов; самая частая тема — этап входа (17,3%).
- Регрессия разделила вклад тем в оценку:

| Категория жалобы | Эффект на оценку, звёзд |
|---|---|
| Вход, фейсконтроль, охрана | **−2,73** |
| Персонал, сервис | −1,62 |
| Музыка, цены, бар, помещение | от −0,97 до −0,59 |
| Безопасность, контингент, платный вход | неотличимо от нуля |

- Вход опережает следующую категорию более чем на звезду, интервалы не пересекаются. Темы, которые выглядели тяжёлыми по средним оценкам, самостоятельного вклада не имеют — они сопровождают жалобы на вход.
- Гипотеза подтвердилась частично: частая тема может быть слабой (помещение — 9,6% отзывов, −0,59), но редких тем с сильным эффектом не нашлось.
- **Рекомендация:** начинать с процедуры входа — это и самая частая, и самая тяжёлая проблема, и её можно улучшить без капитальных затрат (критерии отбора, обучение охраны, объяснение отказа). Доля жалоб на вход по клубам — от 3% до 54%, поэтому приоритеты конкретного заведения стоит смотреть отдельно.

## Структура репозитория
```
clubs-reviews-analysis/
├── clubs_project.ipynb        # основной ноутбук: EDA, LLM-разметка, анализ
├── .env.example               # шаблон для API-ключей
├── src/
│   ├── club_reviews_api.py    # выгрузка отзывов через SerpApi
│   └── prompt.txt             # системный промпт классификатора
└── data/
    ├── club_reviews.csv                 # сырые отзывы (1 600)
    ├── clubs.txt                        # список клубов
    ├── benchmark1.xlsx                  # ручная разметка (149)
    ├── proxyapi_benchmark_pred1.csv     # предсказания LLM на эталоне
    ├── full_reviews_predictions.csv     # предсказания LLM на всех отзывах
    └── club_reviews_labeled.csv         # итоговый размеченный датасет
```

## Как запустить
```bash
cp .env.example .env   # вписать ключи PROXYAPI_KEY и SERPAPI_API_KEY
jupyter notebook clubs_project.ipynb
```
Предсказания LLM сохранены в `data/` как чекпоинты: уже размеченные отзывы повторно в API не отправляются.

## Ограничения
- Собраны только последние отзывы (около 64 на клуб), а не вся история: медианное покрытие — 10% отзывов клуба, у самых популярных — около 1%.
- Анализ описательный, не причинный: регрессия показывает связь темы с оценкой при прочих равных, а не эффект вмешательства.
- Для редких тем (музыка, безопасность) качество классификатора оценено на единичных примерах.

## Стек

- **Обработка и статистика:** pandas, numpy, statsmodels (OLS, интервалы Уилсона)
- **Визуализация:** matplotlib, seaborn
- **LLM-классификация:** OpenAI SDK, Gemini 2.5 Flash через ProxyAPI, python-dotenv
- **Оценка качества модели:** scikit-learn (precision, recall, F1)
- **Среда:** Jupyter Notebook
